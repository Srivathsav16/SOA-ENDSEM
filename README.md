# PostgreSQL Credential Validation

## Requirements
- JDK 17
- Maven (or use the Maven wrapper generated by your IDE)
- PostgreSQL
- Spring Tools for Eclipse (STS)

## 1. Create the database
In pgAdmin Query Tool or `psql`, run:

```sql
CREATE DATABASE credential_db;
```

## 2. Configure PostgreSQL
Open `src/main/resources/application.properties` and set
`spring.datasource.username` and `spring.datasource.password` to your PostgreSQL credentials.
Do not commit real passwords to public repositories.

## 3. Import and run in STS
1. Extract this ZIP.
2. In STS, select **File > Import > Maven > Existing Maven Projects**.
3. Select the extracted project folder and finish the import.
4. Wait for Maven dependencies to download.
5. Open `CredentialValidationApplication.java`.
6. Select **Run As > Spring Boot App**.

Hibernate creates the `app_users` table. On first startup, the application creates this sample account using a BCrypt password hash.

## 4. Sample login
- Username: `student`
- Password: `Lab@123`

Swagger UI: http://localhost:8080/swagger-ui.html

Open `POST /api/auth/login-db`, click **Try it out**, and send:

```json
{
  "username": "student",
  "password": "Lab@123"
}
```

Expected HTTP 200 response:

```json
{
  "message": "Authentication Successful"
}
```

Try a wrong password to receive HTTP 401 and `Authentication Failed`.

## Endpoint
`POST http://localhost:8080/api/auth/login-db`

Request body:

```json
{
  "username": "student",
  "password": "Lab@123"
}
```

## Viva answers
1. **How does username lookup help prevent SQL injection?** Spring Data JPA uses a parameterized query for `findByUsername`, instead of concatenating user input into SQL.
2. **Why use BCrypt?** BCrypt stores a salted, one-way password hash, so the original password is not stored in the database. `matches()` verifies the entered password against the hash.

## Important
This is a lab demonstration. Use HTTPS, rate limiting, stronger account management, and environment variables or a secret manager for real applications.
